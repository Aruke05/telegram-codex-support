# 产品与运营要求

涉及后台页面、Telegram 命令、账号、保留策略、前端体验、上线或新功能设计时读取本文件。

## Telegram 与账号

- 群在网页后台动态配置，只有白名单群普通消息进入客服处理。
- Bot `/start` 与 `/info` 为全局身份查询；`/info` 自查、指定用户名和回复他人查询均开放。其他命令和消息遵循白名单/角色规则。
- 同时支持 Bot 与个人账号，默认 Bot；特殊群可指定个人账号。账号更换后应通过重新配置和导入 SQLite 恢复。
- 用户名、用户 ID 与角色白名单由后台维护，群管理员身份仅供参考。
- 技术群只接收机器人告警，由人工回原群；机器人不能在技术群代替人工处理。
- 命令说明和后台文案使用中文。

## 后台信息架构

- 固定主菜单：运行概览、项目管理、群与账号、客服记录、AI 记忆库、接口文档、模型与运行、导入导出、系统设置。
- 项目管理统一维护代码、服务、服务器、数据库和群归属；群选择项目/服务，不重复填写连接细节。
- 客服记录使用问题线程工作台：实时区与游标分页历史区分离；详情持续显示原问题、补充、附件、输入版本、作废结果、最终回复与纠正入口。
- 项目/服务/群/发送人/时间/分页数量放入“更多筛选”。窄屏详情使用抽屉，禁止横向溢出。
- 客服记录使用游标分页和项目/群/状态/时间组合索引，禁止随数据增长退化的深层 OFFSET。
- 人工纠正和新增规则从 AI 记忆库或客服记录发起，不建立重复知识模块。
- 不提供“敏感信息检查”菜单，只保留机器人发送前的确定性阻断。
- 接口文档分印度与非印度；非印度使用交易类型/银行编码，印度遵循对应代码与印度文档。

## 保留和同步

- 客服原问题、回复、运行状态与附件元数据保留 90 天并小批量清理；AI 对话和客服聊天下载到本地的附件实体文件只保留 3 天，之后保留文件名、类型、大小与已提取文字，但不再提供原文件下载。仍被生成或学习任务使用的文件等任务结束后再清理；由人工纠正派生的有效记忆永久保留，但不能因此永久保存聊天敏感参数。
- 每小时代码同步只处理至少绑定一个已启用客服群的服务；群启用后到期调度立即补同步。
- MagicBook 与接口文档保留脱敏静态快照。

## 开发与验收

- 新能力制定实施计划前，调研官方文档与活跃开源项目的成熟做法，并说明适用性；不能照搬违反本项目边界的设计。
- Git 提交、推送说明和状态反馈使用中文。
- 除非用户明确要求，不提交临时测试文件或测试代码。
- 前端保持单进程托管的轻量原生 TypeScript/CSS。
- 新页面、抽屉和弹窗同时验证浅色/深色、间距、滚动与小屏操作；视觉风格克制、清晰、易用。
- 上线验收只在用户指定 Linux 服务器执行，本机运行不能作为生产结论。
