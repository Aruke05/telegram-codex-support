# 运行与记忆

涉及 SQLite 数据架构、知识版本、导入导出、模型运行或部署时读取本文件。

## 数据架构

- 运行数据使用本机嵌入式 SQLite，不依赖外置数据库服务。
- 产品只提供一个“AI 记忆库”，内部严格分为不可变固定规则、追加式原始证据、版本化 AI 记忆三层。
- 群配置、群 ID、角色、固定规则、证据、记忆、回复、冲突与审计保存在 SQLite。
- Bot Token、个人账号 API Hash、登录 Session 等客服账号凭据必须加密保存且禁止进入迁移库。
- 项目、仓库、分支、服务器和数据库连接信息存入 SQLite，不得进入 Git。连接凭据与可回答知识必须逻辑隔离，不能进入知识检索、客服记录、普通日志或 Telegram 回复。
- MagicBook 与印度/非印度接口文档只保留脱敏、可版本管理的静态快照并建立检索索引。

## 记忆模型

- 固定规则只能读取，不得由 AI 修改、降级或删除。
- 原始证据只能追加，不能覆盖或硬删除；人工规则、纠正、消息、附件解析、提交、接口文档、MagicBook 快照与 AI 观察都属于证据。
- 派生记忆每个版本记录服务、地区、分支、有效时间、风险、置信度、状态与证据引用。
- 人工纠正和新增规则先写高优先级证据，再生成新当前版本；旧版本标记为已替代。纠正原文完整保留在证据层，active 记忆只派生适用条件和语义化处理原则，不把历史正确回答当作可发送模板。
- AI 自动学习只能新增候选证据和版本，不能静默更新/删除历史或采用最后写入覆盖。
- 冲突证据同时保留。当前代码优先于旧知识；强制人工规则优先于普通记忆。
- 只有高频重复、无冲突且获得代码、文档或独立历史证据支持的低风险知识可自动生效。资金、签名、权限、安全和生产操作知识永不自动生效。
- 后台整理只在空闲期批量去重、关联、合并和标记过期。

## 导入导出

- 主迁移格式是可直接校验和读取的 SQLite 数据库，不使用 JSON。
- 迁移库包含项目/代码/群配置、角色、允许迁移的连接信息、固定规则、全部证据/记忆版本、保留期内回复和审计；客服账号凭据与商户密钥不得进入迁移库。
- 新电脑先配置 Bot/个人客服账号，再导入 SQLite，并按账号类型自动重新绑定群。

## 运行闭环

- 回答与记忆使用 SQLite `model_profiles` 中的独立模型配置。
- 回答超时始终读取当前 `answer.timeoutSeconds`；超时必须向运营发送诚实兜底，不能写死时长或只升级不回复。
- Codex 通过本机 CLI 的临时无状态会话运行并返回结构化 JSON。路由/学习保持 `read-only`；回答会话按已批准配置运行，仅获得当前群绑定服务的临时资源。
- 回答临时目录权限为 `0700`，会话后立即清理；提示词、结果和 CLI 错误不得进入普通日志。
- 现有高权限凭据下的只读主要依赖规则，不能宣称硬隔离。真正硬隔离需生产端只读 SSH/forced-command、数据库只读账号和 Redis 只读 ACL。
- Bot 使用长轮询并持久化 update offset；个人账号使用 Teleproto。消息先落库再异步生成。
- AI 只生成提案，确定性代码负责去重、风险升级、冲突保留和状态流转。
- 低风险记忆自动生效至少需要两条不同回复记录以及当前提交中真实存在的代码文件依据。
- 运行状态、模型配置、手动代码同步和手动学习统一位于“模型与运行”。
- 常驻服务只在用户指定的 Linux 服务器部署/验收；本机只编辑与准备，不作为上线健康结论。远端固定监听 `127.0.0.1:3210` 并由 systemd 托管。
