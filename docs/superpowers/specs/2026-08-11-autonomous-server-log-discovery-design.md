# 回答 AI 自主服务器日志发现设计

## 目标

回答 AI 取得当前群绑定服务的服务器后 自己根据代码 进程 工作目录 systemd 容器和文件系统发现本题日志 不再依赖预设服务名 `sfzf-service` 或固定 `logs` 目录

读取范围不按日志文件名或目录做白名单 但仍只能访问当前绑定服务器 远端操作必须只读 大日志必须按时间 关键词和条数限量 最终输出继续脱敏

## 已确认问题

当前回答会话已经使用 `danger-full-access` 并能通过临时 `ssh_config` 登录绑定服务器 实际服务器测试也能读取 journald 和 Java 文件日志 因此问题不是模型没有服务器权限

现有命令证据校验只接受极少数固定形式 `systemctl is-active <unit>` `journalctl -n ...` 以及路径中必须出现 `log` 或 `logs` 的 `tail` 这会丢弃模型通过进程工作目录发现的其他日志

回答过程中即使命令真实执行成功 `investigation-service` 仍把命令输出清空 并统一标记为 `skipped` 导致后台看不到模型实际查到的服务器和日志证据

固定诊断接口仍把服务名写死为 `sfzf-service` 迁移后真实 Java 应用使用文件日志时会产生服务不存在或 journald 无记录的误导结果

## 成熟方案参考

Kubernetes 官方日志架构把应用 stdout stderr systemd journal 和节点文件日志视为不同但并列的日志来源 不假设全部日志都在单一位置

Grafana Loki 官方文档先通过服务 文件名 主机等来源标签发现日志流 再使用时间和内容过滤缩小查询范围 说明成熟产品的边界应是来源和查询规模 而不是固定某个日志路径

本项目当前只有服务器直连能力 不引入新的日志平台 复用上述“先发现来源 再限量读取”的方法

## 采用方案

### 服务器自主发现

提示回答 AI 在读取当前服务代码后按实际环境选择以下来源

- 进程与工作目录 `ps` `/proc/<pid>`
- systemd 单元与 journald
- Docker 或 Kubernetes 容器标准输出
- 应用工作目录和服务器上的文件日志

不预设服务名 日志目录 文件后缀或框架 模型可以在当前服务器上先发现再读取

### 只读命令证据分类

本地代码和数据库助手继续使用现有严格校验

SSH 命令改为两层判断

1 确认只能通过本题临时 `ssh_config` 访问 `support-N` 别名
2 拒绝写文件 删除 重启 部署 修改权限 安装软件 结束进程 数据库写入 Redis 写入和网络下载等明显可变操作

通过只读判断后 根据命令内容分类为 `server` `log` 或 `redis` 不再按日志路径白名单判断

Codex CLI 可能把实际 SSH 命令包装为 shell 字符串或把命令数组展开为一行 校验器同时识别直接 SSH 和这种外层包装 但两种形式都必须命中本题 `ssh_config` 与 `support-N` 别名

### 真实证据记录

模型命令事件由 Codex CLI 返回实际命令 输出和退出码

- 退出码为 0 且有输出记为 `confirmed`
- 退出码为 0 且无输出记为 `not_found`
- 非 0 或未知退出码记为 `failed`

后台展示脱敏后的限量输出 不再把真实命令统一写成未采信

数据库查询仍由父进程独立复核 不改变现有数据库安全边界

### 固定诊断接口

移除 `service_status` 和 `recent_logs` 对 `sfzf-service` 的写死

固定接口只做通用服务进程概览和通用 journald 计数 具体应用日志由回答 AI 自主发现

## 安全边界

- 只允许当前群绑定服务的服务器别名和临时 SSH 配置
- 远端只读规则不等于生产端硬隔离 真正不可绕过的隔离仍需只读 SSH 账号 forced-command 数据库只读账号和 Redis ACL
- 拒绝输出重定向 下载 安装 重启 删除和其他明显变更命令 允许只读管道 输入脚本 命令替换和多步发现 以便模型适配不同日志格式
- 日志结果最多保留现有命令观察上限并在后台再次脱敏截断
- 运营回复禁止出现服务器地址 数据库地址 私钥 密码 Token Session 连接串和远端绝对路径

## 验证

不新增或提交测试文件

先在生产旧版本用一次性脚本证明任意目录日志 `tail` 容器日志和日志发现命令不会成为可信证据

实现后提交推送并在 `DEPLOY_HOST` 构建 运行现有测试 再用一次性脚本验证自主只读日志命令通过 写命令仍被拒绝 固定诊断不再出现 `sfzf-service`

最后用真实回答 Codex 连接绑定服务器 自主找到 Java 文件日志并在后台排查轨迹中记录脱敏后的真实输出
