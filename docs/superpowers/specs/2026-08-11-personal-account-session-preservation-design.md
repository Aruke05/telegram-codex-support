# 个人账号启用时保留登录会话设计

## 背景

个人 Telegram 账号完成验证码和两步验证后会把登录 session 保存到加密凭据中。后台随后只提交 `enabled: true` 时，更新校验错误地把未提交的 `session` 补成空字符串，导致刚保存的登录会话被清空，账号重新变成“需要登录”。

## 目标

- 创建个人账号时允许缺省 session，并保存为空字符串。
- 更新个人账号时，只有请求明确包含 session 才修改 session。
- 单独修改名称或启用状态时保留现有 session。
- 修改 API ID、API Hash 或手机号时仍按现有安全逻辑清空 session 并要求重新登录。

## 方案

把 session 的基础字符串约束提取为无默认值的 `userSessionSchema`。创建凭据继续显式使用空字符串默认值；更新请求直接使用 `userSessionSchema.optional()`，避免 Zod 在字段缺失时应用内层默认值。

本次不改登录流程、凭据加密方式、数据库结构和前端请求协议，也不新增仓库测试文件。回归使用服务器临时目录中的一次性脚本验证“保存 session 后只启用账号，session 保持不变”，脚本执行后立即清理。

## 验收标准

- 修复前的一次性回归脚本能稳定复现 session 被清空。
- 修复后相同脚本通过，账号为启用状态且 session 原值保留。
- 类型检查、现有测试和构建全部通过。
- 生产服务部署并恢复健康后，个人账号可以重新完成登录和启用。
