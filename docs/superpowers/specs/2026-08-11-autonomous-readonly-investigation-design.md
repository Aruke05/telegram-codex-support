# AI 客服自主只读排查设计

## 目标

回答 AI 根据当前问题自主阅读绑定服务代码并选择服务器 日志 数据库 Redis 或接口文档完成排查

业务流程不再由程序写死到订单主表 `sys_log` `channel_log` 或任何固定表名和固定步骤

程序只保留不可绕过的服务边界 只读边界 敏感信息出站拦截和代码缺陷升级门禁

## 已确认问题

当前实现同时让 AI 排查 又用确定性代码检查订单主记录 `sys_log` `channel_log` 等固定步骤

模型结果连续三次没有满足固定证据门禁时 程序会丢弃模型结果并生成未查清兜底 随后再把兜底强制改成追问商户下单参数和平台响应

这使程序根据运营消息里有没有出现固定文字来判断资料是否足够 忽略了 AI 已经拥有代码 服务器 数据库 Redis 和订单号 可以继续自主查证

错误回复的 `reply_memory_refs` 为空 证明最终固定追问不是 AI 记忆生成 而是外层兜底覆盖

## 方案比较

### 方案一 保留固定证据门禁

继续要求订单主记录 `sys_log` `channel_log` 等固定步骤

优点是行为看似统一 缺点是不同服务表结构和日志架构不同 外层规则会覆盖 AI 的正确判断 本次问题正是该方案造成

### 方案二 完全取消所有外层限制

AI 自主排查并直接发送任何结果

灵活性最高 但可能产生生产写入 跨服务查询 敏感信息泄漏或无证据升级 不符合本项目安全边界

### 方案三 自主排查加最小安全门禁

采用此方案

AI 自己阅读代码并选择查询路径 程序不校验表名 步骤名或业务证据顺序

外层只校验禁止写入 禁止跨服务 禁止敏感信息出站 以及只有当前代码明确缺陷才允许升级

## 自主排查流程

1. 每次回答前同步当前群绑定服务的 Java 与 Web 仓库共同分支
2. 把当前服务代码快照 服务器 数据库 Redis 和附件放入本题临时资源工作区
3. AI 先理解运营真正询问的内容
4. AI 按需阅读当前代码确认业务实现 表结构 日志结构 配置和调用关系
5. AI 自己决定是否 SSH 查日志 查询数据库 查询 Redis 核对 nginx 或读取接口文档
6. AI 根据工具返回继续排查 直到足以回答或确实缺少外部信息
7. 只有 AI 实际尝试现有资源后仍缺少必要数据时 才向运营追问具体缺少的内容
8. 出站前执行最小安全检查后发送

程序不再规定订单必须先查哪张表 不再根据商户侧或上游侧关键词指定表名 不再检查调查步骤标题

## 提示词边界

删除以下内容

- 订单主记录 `sys_log` `channel_log` 的强制顺序和固定步骤名
- 缺少固定数据库步骤就重答的指令
- 订单无法确认时固定追问商户参数和平台响应
- 三次校验失败后把结果改成固定资料追问

保留并强化以下内容

- 当前群绑定服务是唯一排查目标
- 先看当前代码 再根据代码决定查询位置和字段
- 有订单号 地址 IP 时间范围等定位信息时先使用现有资源 不让运营重复提供
- 数据库和 Redis 从绑定服务器内只读访问
- 生产代码 配置 数据库 Redis 和服务禁止写入 重启和部署
- 所有结论必须忠于实际证据
- 只有当前新鲜代码中定位到仓库 文件和行号的缺陷才允许升级
- 最终回复不得泄漏凭据 商户密钥或基础设施地址

## 确定性代码职责

### 保留

- 代码同步及同服务历史完整快照降级
- 临时资源工作区和服务凭据隔离
- SQL 只读语句限制和查询数量限制
- SSH 非交互和超时
- 敏感信息出站拦截
- 明确代码缺陷升级验证
- Telegram 发送状态和线程版本控制
- 调查轨迹和数据库查询审计

### 删除

- `missingRequiredInvestigationEvidence` 对固定表和步骤的判断
- `missingOrderEvidenceReply` 对运营消息关键词的固定资料追问
- `requestMissingOrderEvidence` 对模型答案的覆盖
- 因缺少业务证据步骤而进行的三轮强制重答

调查轨迹和查询审计只作为后台复核证据 不参与业务答案放行

## 失败处理

模型输出包含禁止升级措辞 技术群内部文案 过度技术化内容或敏感信息时仍允许重答

三次安全重答仍失败时只发送中性的安全兜底 不得猜测缺少什么资料 也不得自动生成商户参数追问

工具连接失败时由 AI 使用其他可用证据继续排查 并在确实无法回答时用人话说明当前缺少哪项业务信息

## 记忆边界

人工纠正和 AI 记忆只提供历史经验和回答偏好 不得规定当前服务必须使用某张表

当前代码和实时只读证据始终高于记忆

## 验证

不新增或提交测试文件

使用一次性断言验证

- 固定表名证据门禁和固定资料追问已移除
- 提示词要求 AI 先看代码并自主选择服务器 数据库 Redis 和日志
- 只读 敏感信息 服务归属和升级门禁仍存在
- 原问题包含订单号但没有商户请求参数时 不再被代码改写成固定追问
- 安全校验连续失败时不再推断运营缺少哪些资料

部署后使用 MCBPay 原问题运行真实回答会话 验证 AI 自主读取代码和生产只读资源并形成结论
